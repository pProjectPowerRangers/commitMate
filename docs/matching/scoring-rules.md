# StudyMatch 계산 규칙 v1.0 (S0-4 확정본)

> 담당 C(seoyeon) · 확정 2026-11-26 · 근거: 현서 기획서 "3. 계산 규칙"
> 점수는 팀장의 판단을 돕는 **보조 지표**이며 실력 평가가 아니다. 협업 온도는 매칭 점수에 넣지 않는다.

## 0. 기호
| 기호 | 뜻 |
|---|---|
| L(u,s) | 사용자 u의 기술 s 레벨 (1~4, 미보유 = 0) |
| r(s) | 프로젝트 요구 레벨 (1~4, 기본 2) |
| w(s) | 중요도: 필수 3, 우대 1 (초기값) |
| T | **승인된** 팀원 집합 (팀장 포함, 검토 중 지원자 제외) |

## 1. 공식
| 항목 | 공식 |
|---|---|
| skillMatch | 100 × Σ w·min(1, L/r) / Σ w |
| interestMatch | 프로젝트 분야가 관심 분야에 있으면 100, 없으면 0 |
| availabilityMatch | 70 × min(1, 사용자 주당 시간 / 기대 시간) + 30 × (시간대 하나라도 겹침 ? 1 : 0) |
| matchScore | 0.6·skillMatch + 0.2·interestMatch + 0.2·availabilityMatch |
| Coverage(T) | 100 × Σ w·min(1, max_{m∈T} L(m,s) / r) / Σ w (팀 최고 레벨, 합산 아님) |
| contribution(a) | 100 × (Coverage(T∪{a}) − Coverage(T)) / (100 − Coverage(T)) |

## 2. 확정한 결정
| # | 항목 | 결정 |
|---|---|---|
| 1 | 반올림 | 계산은 정확한 분수로 끝까지 유지, **화면 표시 직전에만 정수 HALF_UP**. 정렬은 반올림 전 값. (double 금지: 12.5가 12.4999…가 될 수 있음. L/r 분모를 12로 통일하면 분자·분모가 모두 정수) |
| 2 | 레벨 | 미보유 0, 부분 충족은 선형 L/r, 요구 레벨 초과분은 점수 미반영(추천 이유 문구로만 표시), 요구하지 않은 기술은 계산 제외 |
| 3 | 커버리지·기여도 | 팀 커버리지 100이면 기여도 **값 없음**, 카드에 "요구 기술을 모두 충족한 팀", 정렬은 매칭 점수순. 기여도는 항상 0~100. 정원 초과 역할 지원자도 계산하고 배지만 추가 |
| 4 | 가능 시간 | 사용자 시간이 기대 시간보다 많아도 상한 70. 시간대는 겹침 여부만. 비어 있으면 해당 파트 0점 + 추천 이유 "가능 시간 미입력" |
| 5 | 비율·가중치 | 60/20/20, 필수 3·우대 1. **초기값**: 설정(application.yml)으로 빼고 Sprint 2 시드 데이터로 조정 |
| 6 | 정렬 동점 | 기여도 desc → 매칭 점수 desc → 지원일 asc |

## 3. 예시 계산표 (단위 테스트와 동일)
요구 기술: Java(필수 r2), Spring Boot(필수 r2), React(필수 r2), Docker(우대 r2), 중요도 합 10.
현재 팀: 팀장(Java 3, Spring Boot 3) → 커버리지 **60**

| 지원자 | 보유 기술 | skillMatch | 합류 후 커버리지 | 기여도 (정확값 → 표시) |
|---|---|---|---|---|
| A | Java 4, Spring Boot 4, Docker 1 | 65 | 65 | 12.5 → **13** |
| B | React 3, Java 1, Docker 2 | 55 ("필수 Spring Boot 미보유 (팀이 충족 중)") | 100 | 100 |
| (없음) | — | 0 | 60 | 0 |
| React 1만 | React 1 | 15 | 75 | 37.5 → 38 |

매칭 점수 예시 (기대 10h·주말):
- A: 분야 일치, 10h·주말 → 0.6×65 + 20 + 20 = **79**
- B: 분야 불일치, 6h·주말(availability 72) → 33 + 0 + 14.4 = 47.4 → **47**

## 4. 경계 케이스
| 상황 | 결과 |
|---|---|
| 팀 커버리지 이미 100 | 기여도 없음, 매칭 점수순 정렬 |
| 팀장이 요구 기술을 하나도 없음 (커버리지 0) | 기여도 = 합류 후 커버리지 |
| 레벨 1 세 명 vs 레벨 3 한 명 (r=3) | 최댓값 기준이라 각각 1/3, 1 (합산 안 함) |
| 승인으로 팀 커버리지 100 도달 | 남은 지원자 기여도가 모두 "없음"으로 바뀜 |
| 사용자 주당 시간 0 / 미입력 | 시간 파트 0점 |
| 요구 r=3, 레벨 1 / 2 | 33.33 → 33 / 66.67 → 67 |
| 레벨 0·5·null, 요구 레벨 0·5 | IllegalArgumentException |
| 요구 기술 0개 | IllegalArgumentException (등록 시 필수 기술 1개 이상 강제) |
| 프로젝트 기대 시간 0·null, 시간대 없음 | IllegalArgumentException |

## 5. 다른 담당에게 요청할 것
- **A(현서)**: 프로필에서 주당 가능 시간·선호 시간대 필수 입력, 기술 레벨은 1~4만 허용
- **B(hwangddijoon)**: 프로젝트 등록 시 필수 기술 1개 이상, 요구 레벨 1~4, 기대 시간 1~40, 시간대 1개 이상 검증
- **팀 전체**: 예시표의 A 기여도 13은 "12.5를 HALF_UP"한 값임을 기획서에 각주로 추가
