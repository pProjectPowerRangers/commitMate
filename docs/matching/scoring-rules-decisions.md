# CommitMate 계산 규칙 결정 기록 (S0-4, C 담당 seoyeon)

## 1. 반올림 (2026-11-26 확정)
- 계산은 정수 분자/분모(또는 BigDecimal)로 끝까지 유지, 화면 표시 직전에만 정수 HALF_UP.
- 정렬은 반올림 전 값 기준.
- 예시표 A 기여도 12.5 -> 13 (표와 일치).

## 2. 레벨 경계 (2026-11-26 확정)
- 미보유 = 0, 부분 충족은 선형 min(1, L/r) (기획서 그대로, 예시표 유지).
- 요구 레벨 초과분은 점수에 반영 안 함 (추천 이유 문구로만 "레벨 4 / 요구 2").
- 요구하지 않은 기술은 점수 계산에서 제외.
- 레벨이 1~4 밖이거나 null이면 계산 클래스에서 IllegalArgumentException (입력 검증은 A 프로필 API).

## 3. 커버리지·기여도 경계 (2026-11-26 확정)
- 팀 T = 승인된 팀원(팀장 포함)만. 검토 중 지원자 제외. 승인 시 남은 지원자 기여도가 바뀜.
- 요구 기술 0개: 등록 시 필수 기술 1개 이상 강제(B), 계산기는 예외.
- 기여도 >= 0 불변식(최댓값 기준이라 커버리지 단조 증가) -> 테스트로 고정.
- 정원 초과 역할 지원자도 점수 계산, 배지만 추가.
- 팀 커버리지 100: 기여도 값 없음(null / FULLY_COVERED), 카드에 "요구 기술을 모두 충족한 팀", 기본 정렬은 매칭 점수순으로 전환.

## 4. availability 경계 (2026-11-26 확정)
- 프로젝트 기대 시간 1~40, 시간대 1개 이상 필수(B 등록 검증). 기대 시간 0/null이면 계산기 예외.
- 사용자 시간이 기대 시간보다 많아도 시간 파트 상한 70.
- 시간대는 겹침 여부만(1개 이상 겹치면 30).
- 사용자 가능 시간·시간대는 프로필 필수 입력(A에 요청). 그래도 비어 있으면(기존·시드) 해당 파트 0점 + 추천 이유 "가능 시간 미입력".
- 예: 기대 10h, 사용자 6h, 주말 겹침 -> 70*0.6+30 = 72.

## 5. 비율·가중치 (2026-11-26 확정)
- matchScore = 0.6 skill + 0.2 interest + 0.2 availability, 필수 3 / 우대 1 (기획서 그대로).
- 초기값. application.yml 등 설정으로 빼고 Sprint 2 시드 데이터로 조정.
- 정렬 동점: 기여도 desc -> 매칭 점수 desc -> 지원일 asc. 팀 커버리지 100이면 매칭 점수 desc -> 지원일 asc.
